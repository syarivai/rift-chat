# i18n

The app ships **English (`en`)**, **Malay (`ms`)**, and **Indonesian (`id`)**. All three are
LTR, so there is no RTL layout work.

## How the language is chosen

1. The user's explicit choice in Settings, if set (persisted in MMKV).
2. Otherwise the device locale, read via `expo-localization`'s `getLocales()[0].languageCode`.
3. Otherwise `en`.

`en` is also the fallback chain target: a key missing from `ms` or `id` renders the English
string rather than the raw key.

## The three packages

Each does a distinct job — see
[Tech stack](./tech-stack.md#why-these-three-for-i18n) for the full explanation.

| Package             | Job                                                            |
| ------------------- | -------------------------------------------------------------- |
| `i18next`           | Catalogs, key lookup, interpolation, plurals, fallback         |
| `react-i18next`     | `useTranslation()`, and re-rendering when the language changes |
| `expo-localization` | Reading the device locale (the only native piece)              |

## Catalog layout

```text
src/core/i18n/
├── index.ts              # init, language resolution, fallback chain
└── locales/
    ├── en.json
    ├── ms.json
    └── id.json
```

One flat JSON file per locale, grouped by screen or domain:

```json
{
  "chats": {
    "title": "Chats",
    "empty": "Tap to start chatting",
    "searchPlaceholder": "Search contacts"
  },
  "chat": {
    "composerPlaceholder": "Message",
    "sendFailed": "Not delivered. Tap to retry.",
    "blocked": "You blocked this contact"
  }
}
```

## Key conventions

- Namespace by screen or domain, then by role: `chat.composerPlaceholder`.
- Keys are `camelCase` and describe **purpose**, never the English text. `chats.empty`, not
  `chats.tapToStartChatting` — the latter becomes a lie the moment the copy changes.
- No sentence assembly from fragments. Translate whole sentences; word order differs between
  languages and concatenation produces nonsense.
- Interpolate rather than concatenate: `"lastSeen": "Last seen {{time}}"`.

## Plurals

English distinguishes `one` and `other`. **Malay and Indonesian have no grammatical plural** —
both collapse to CLDR's `other`, and i18next handles that automatically:

```json
// en.json
{ "chat": { "messageCount_one": "{{count}} message", "messageCount_other": "{{count}} messages" } }

// id.json
{ "chat": { "messageCount_other": "{{count}} pesan" } }
```

Call it with `t('chat.messageCount', { count })`. Never build a count string by hand.

## Dates and relative times

Use `Intl.RelativeTimeFormat` with the active language, not a hardcoded suffix. Hermes ships
Intl, so no date library and no locale packs are needed:

```ts
new Intl.RelativeTimeFormat(language, { numeric: 'auto' }).format(-3, 'minute');
// en → "3 minutes ago"   id → "3 menit yang lalu"
```

## Adding a string

1. Add the key to **`en.json` first** — it is the fallback and the source of truth.
2. Add the same key to `ms.json` and `id.json`. Never leave one out; a missing key silently
   falls back to English, which reads as a bug in the other two locales.
3. Use it via `const { t } = useTranslation()` — never a literal in JSX.

The `rn-ui-checker` agent flags string literals that reached JSX without a key, and keys
present in one catalog but not the others.

## Adding a language

1. Add `src/core/i18n/locales/<code>.json` with every key from `en.json`.
2. Register it in `src/core/i18n/index.ts`.
3. Add it to the Settings language picker.
4. Re-check the layout: translated strings are frequently longer than the English source, and
   tab labels and buttons are where that first breaks.
